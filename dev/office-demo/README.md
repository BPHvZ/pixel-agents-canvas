# Local office scenario demo

Run `node dev/office-demo/server.js` from the repository root, then open the loopback URL it prints. Run the scenario contract alone with `node --test test/office-demo.test.js`; it also runs as part of `npm test`. The separate launcher lists stable scenario IDs and named visual capture frames; select one or use `?scenario=<id>&frame=<frame-id>` for a reproducible direct link. **Reset / replay** starts a fresh production server and office-world instance, replays that frame's scenario steps through production state reads, and advances its deterministic clock to the declared frame time. The viewport selector resizes the production page itself; the browser's native reduced-motion preference is honored by the production stylesheet.

The launcher substitutes only controller snapshots produced through `createOfficeState` at the `createOfficeServer` input boundary. It uses the production preference store in a per-preview temporary directory seeded from the synthetic fixture and deleted when that preview closes; it never reads or writes the developer's actual preference store. It uses the production state route, `renderHtml`, `office-client.js`, `office-world.js`, and `office.css`; there is no markup rewriting, iframe `srcdoc`, mocked global `fetch`, or scenario code in the extension entry point. Local provider action methods are inert no-ops. No provider adapter, host API, credentials, or real agent session is loaded. Scenario fixtures are synthetic and stay outside the released extension.

Capture named review frames with `python3 dev/office-demo/capture_scenarios.py [--output /path/to/captures]`. This explicit command requires Python Playwright and local Chrome or Chromium, visits every catalog-declared scenario/frame URL plus one stable `?scenario=<id>` default-state URL for each scenario without visual frames, emulates each frame's reduced-motion and viewport settings, checks declared production scene/effect/pose/status/dialogue targets, inert provider-action endpoints, and production preference persistence/reload/reset isolation, and saves full-page screenshots with the development-context banner visible. The default output directory is under the system temporary directory. Screenshots are review artifacts, not golden-image tests; this command is not part of `npm run check`.
