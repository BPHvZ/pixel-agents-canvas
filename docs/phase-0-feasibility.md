## Phase 0 conclusion

Codex CLI 0.163.0 can enumerate existing local threads with metadata-only resume and paginated `thread/list`; archive filtering works and status notifications arrived without starting a turn. However, the list schema includes `preview` even when requesting DB-only mode. Default scanning can inspect rollout JSONL; `useStateDbOnly: true` avoids that repair scan but can fail when the state database cannot answer. Local Codex app-server startup/shutdown is live-tested in VS Code Insiders and in the user's GitHub Copilot App project session; the App-host canvas successfully connected, created an empty ephemeral idle thread without starting a turn, then the child was terminated and is no longer running. Canvas removal stopped its renderer while the session extension remained active; direct `onClose` outcome and host/session shutdown cleanup remain unverified. Thread status and turn completion are separate: `ThreadStatus` has no completed state, while the distinct turn-completed event reports `completed`, `interrupted`, `failed`, or `inProgress`. Preserve that distinction rather than deriving one from idle/archive.

Host docs and the installed runtimes support different distribution paths: VSIX for VS Code, `.github/extensions`/plugins for Copilot App. VS Code web extension host cannot spawn executables; desktop Node extension host can. Copilot App 1.1.30 bundles a Node extension bootstrap and SDK lifecycle hooks; project-specific extension launch, renderer, Codex app-server startup, and an empty ephemeral thread without a model turn are verified in App session `0cdd3db3-e118-4e38-8254-9460f64dd627`; the child exited cleanly after SIGTERM. The App's BYOK session used `gpt-6-luna (VibeProxy)` with no active paid plan. VS Code docs say generic BYOK works without an account or Copilot plan in a Copilot harness when `chat.agentHost.byokModels.enabled` is enabled. The active VS Code session is registered as `copilotcli`, the project extension is loaded in this window, and the user confirms this very chat is routed through their VibeProxy custom endpoint/ChatGPT subscription with no paid plan; this satisfies the intended third-party custom-endpoint route. Do not conflate the Copilot CLI activity source with proxy/model billing or with VS Code's separate Codex harness. Copilot App session deep links are documented, but applying them to discovered Codex CLI thread IDs is untested; a public VS Code extension navigation API was not found. Official hook documentation does not guarantee prompt data remains transient, on-device, or out of logs. Privacy scope is resolved to the adapter's source-level minimization only, and prompt summarization is deferred; no host-wide zero-egress guarantee is claimed. Navigation scope is resolved: the session instruction opens the canvas, while unsupported cross-session navigation is omitted. The three reference projects contribute concrete designs—AVO status/freshness, Pixel Agents' explicit event adapter seam and reported hierarchy, Agent Office's map/list presentation—but do not establish native Codex discovery or transferable host capability. A local Chrome 152 renderer smoke test passed at the agreed scale of 100 sessions/300 synthetic agents (all records shown; median load plus two animation frames 50.49 ms; no page errors or horizontal overflow); methodology and limits are recorded in [docs/phase-0-rendering-scale.md](./phase-0-rendering-scale.md). A simulated extension-parent SIGKILL test showed the Codex app-server child exits when its stdio parent pipe closes; the Copilot App bundled bootstrap's parent watchdog and normal shutdown have also been tested. These are observed lifecycle paths, not a guarantee for arbitrary failures. Official consent evidence: VS Code workspace trust is documented; Copilot CLI docs state project extensions load in trusted folders or under explicit opt-in; Copilot App canvas docs do not specify a corresponding project-extension consent gate. **Phase 0 decision: GO — approved to proceed to Phase 1.** The user accepts standard host/workspace trust and deliberate use of this project canvas as consent to project-extension execution. Copilot App first-party docs do not promise a separate project-level trust prompt, so the product must not claim one exists. Codex app-server startup remains separately opt-in. Normal cleanup and tested child-process exit paths are accepted for Phase 0; no universal host crash guarantee is claimed. See [docs/phase-0-host-consent-lifecycle.md](./phase-0-host-consent-lifecycle.md).
