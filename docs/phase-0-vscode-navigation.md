# Phase 0: VS Code session navigation and canvas support

**Checked:** 2026-10-17. **Scope:** VS Code Insiders 1.143.0-insider (version supplied for this review), VS Code public extension API, Copilot and Local harnesses, and Canvases Preview. Source review only; no live host/API test. “Unknown” means the cited sources do not establish the claim, not that the capability is absent.

| Question | Finding | Evidence and limitation |
|---|---|---|
| Can an extension navigate to/open/focus another agent conversation by provider/session ID through a documented supported VS Code extension API? | **Verified: no such API is documented in the reviewed public API surface.** The public API reference says it lists APIs available to extension authors and is compiled from `vscode.d.ts`. In the chat declarations, the documented API creates chat participants; there is no session-navigation/provider-ID API in that declaration surface. The generic `commands.executeCommand` API does not itself document a session command or argument contract. | [VS Code API reference](https://code.visualstudio.com/api/references/vscode-api) · [`vscode.d.ts` chat namespace](https://github.com/microsoft/vscode/blob/main/src/vscode-dts/vscode.d.ts#L20118-L20129) · [`vscode.d.ts` commands namespace](https://github.com/microsoft/vscode/blob/main/src/vscode-dts/vscode.d.ts#L10976-L11029). Bounded search: reviewed the public API reference and `vscode.d.ts` for chat/session/agent-session and open/focus/navigation declarations. This is not a claim that no internal or future API exists. The exact 1.143.0-insider bundled declaration file was not separately verified; source links are the reviewed public reference/current `main` declarations. |
| Are there internal workbench session-opening commands? | **Verified: yes, internal implementation exists.** VS Code source defines workbench actions such as `workbench.action.chat.openSessionInEditorGroup`, `...openSessionInNewEditorGroup`, and `...openSessionInNewWindow`, which call an internal chat-widget service with an internal session resource. These are workbench implementation details, not a documented extension API or documented provider/session-ID contract. | [VS Code `agentSessionsActions.ts`](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts#L922-L947) · [side/new-window actions](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts#L984-L1043). `commands.executeCommand` accepts a command ID generally, but the public API docs do not establish these workbench actions as supported extension commands or define a stable external ID-to-session mapping. |
| Does VS Code support Canvases Preview with BYOK in Copilot harness sessions? | **Verified:** BYOK models can be used in Copilot harness sessions when `chat.agentHost.byokModels.enabled` is enabled; the setting enables extension-provided BYOK models in Agent Host sessions. Canvases Preview is documented for VS Code desktop local sessions using the Copilot harness. **Unknown:** the reviewed first-party sources do not explicitly promise or test the specific Canvas Preview + BYOK combination. | [VS Code BYOK docs](https://code.visualstudio.com/docs/agent-customization/language-models#bring-your-own-language-model-key) · [setting declaration](https://github.com/microsoft/vscode/blob/main/src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts#L338-L345) · [1.142 Canvases Preview notes](https://code.visualstudio.com/updates/v1_142#_canvases-preview). The release notes scope canvases to local Copilot-harness sessions; model-access documentation separately scopes BYOK to Copilot-harness chat/Agents sessions. The sources do not connect these two guarantees explicitly. |
| Are canvas extensions available in Copilot harness versus Local harness? | **Verified:** VS Code Canvases Preview is provided by canvas extensions and is documented for Copilot-harness sessions; the release notes describe creating an extension or installing a plugin-provided extension. **Unknown:** the reviewed VS Code sources do not document Canvases Preview for the distinct **Local** harness, so do not infer Local-harness support or its absence. In the Copilot app, first-party docs describe canvas extensions as extension directories with `package.json` and an entry file (for example `extension.mjs`). | [VS Code 1.142 Canvases Preview](https://code.visualstudio.com/updates/v1_142#_canvases-preview) · [Copilot app canvas extension docs](https://docs.github.com/en/copilot/how-tos/github-copilot-app/working-with-canvas-extensions). “Local sessions” in the release note means local execution/scope and should not be confused with the **Local** harness name. |
| Are hooks available in Copilot harness versus Local harness? | **Verified:** both have hook implementations, but they are distinct. Copilot uses the shared Copilot SDK hook implementation; Local has its own events, settings, and payloads. SDK Policy Hooks are not loaded in Local sessions. | [VS Code hooks docs](https://code.visualstudio.com/docs/agent-customization/hooks#choose-the-hook-implementation-for-your-session) · [harness comparison](https://code.visualstudio.com/docs/agents/run/agent-harnesses#compare-agent-harnesses). Hook-file compatibility does not guarantee identical behavior; use the selected harness’s schema. |

**Practical conclusion:** treat cross-session navigation by provider/session ID as unsupported by the *documented public VS Code extension API* on this evidence; do not rely on internal workbench command IDs as a public contract. Canvases are documented for Copilot-harness sessions, BYOK is documented for that harness, but their combined operation is not explicitly specified in the docs. On 2026-10-17, the user's current VS Code Insiders session was active in the `copilotcli` harness with a proxy-backed GPT-6 Luna custom endpoint; this project extension loaded, its canvas rendered, and both Copilot CLI hooks and the independently enabled Codex app-server were active. This is direct host evidence that the *custom endpoint / Copilot CLI harness* combination works in this setup, distinct from generic VS Code BYOK. Canvas Preview support in the separate Local harness remains unestablished.
