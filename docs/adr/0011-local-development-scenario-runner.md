# Local development scenario runner

The local demo is a development-only scenario runner, not a released extension feature. A separate local launcher supplies deterministic, synthetic scenario inputs at the provider/controller-state boundary, while the live application's state normalization, server/client, production markup, renderer, and styles remain unchanged; it uses no real agent sessions or provider data, and scenario selection plus the development/preview indicator stay outside the canvas.

A named, stable-ID scenario catalog is the coverage inventory for every intentional V1 user-visible state, Office vignette/animation, supported responsive layout, and reduced-motion behavior—not every possible provider-data combination. Keep only existing cases that map to this inventory, fill uncovered states, and support manual selection/direct URLs plus deterministic named-frame captures using the existing Playwright harness on an explicit command. Captures are review artifacts, not pixel-perfect golden gates.

## Considered Options

- Continue the standalone page that shares the renderer but rewrites markup and replaces the live state bridge; rejected because it does not validate the actual UI/state path.
- Add scenario routes, flags, or fixtures to the released extension; rejected because it expands the runtime surface and risks scenario injection.
- Selected: a separate local development launcher that substitutes only scenario state and reuses the production path.

## Consequences

The complete demo-only surface is excluded from GitHub-generated source archives with `.gitattributes` `export-ignore`, while remaining in the repository for local development; this preserves ADR 0010's tagged source-snapshot release model. GitHub documents its source archives as generated by `git archive`, and Git documents that `export-ignore` excludes paths from archives ([GitHub docs](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives), [git-archive docs](https://git-scm.com/docs/git-archive#ATTRIBUTES)). Normal tests verify that production routes and inputs cannot load scenarios, generated archives omit demo-only files, and the scenario coverage map has no gaps. The existing Playwright harness captures deterministic frames through an explicit command, without golden-image gates. The external development surface and captured screenshots must make preview context clear so synthetic scenarios are not mistaken for provider-observed work, preserving ADRs 0003 and 0008.
